# 架构与接口

两个模块复用相同的分工：Astra 生成计划，JEV 在当前候选集合里选择动作，本地执行器将动作提交给 SC2。公共信息、当前可见信息、模型选择和游戏执行结果分别记录。

| 项目 | 宏观 | 微观 |
| --- | --- | --- |
| 范围 | 从开局到结束的 Protoss 对局 | 固定兵力的 SMAC-Hard 遭遇战 |
| SDK | BurnySC2 6.5.0 | SMAC-Hard 的修改版 PySC2 |
| 游戏时间 | `realtime=True`，推理期间继续推进 | `realtime=False`，执行一次队伍决策后推进 8 loops |
| Astra | 周期和事件触发的阶段计划 | 每张地图一次、三局复用 |
| JEV | 每次选择一个宏观动作 | 每个存活单位一道 Choice，按输入预算分批 |
| 动作条件 | 科技、资源、产能、空间及计划预算 | 原始 SMAC 合法候选、兼容目标、正常队伍视野 |
| 结果复核 | 时效、当前计划、当前可执行性 | 合法 ID、单位与命令映射、真实游戏时钟 |
| 原始日志 | `events.jsonl` 顺序保存全程 | `events.jsonl` 顺序保存全程 |

宏观计划有结构化的数量目标、资源预留、支出范围、进退阈值及目标区域；这些字段影响候选筛选和执行复核。工人资源分配、折跃门变形以及已选择的军队姿态由本地执行器维护。

微观计划是条件化的地图指导，完整传给每次 JEV 请求；不在本地通过计划裁掉原候选，也没有规则代选。P0 记录单位血盾、冷却、当前订单、距离、射程状态、移动候选、治疗候选和上一轮原生反馈。较大的批次保留全队核心信息，其他单位同轮尚未作出的选择并不已知。

两种模式均限制模型使用当前正常观察。微观额外提供公开地图兵力、出生区域和静态地形，公共先验不等同于迷雾中的实时敌方位置。

源代码导航见 [宏观入口](../macro/README.md) 与 [微观入口](../micro/README.md)。
