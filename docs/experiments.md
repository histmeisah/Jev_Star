# 实验与版本边界

本页登记历史结果与后续实验。公开整理文件和依赖本身没有启动付费对局；用户随后授权的实战批次单列，当前源码版本与历史实验版本分别记录。

## 微观

共同条件：35 张 SMAC-Hard 注册地图、每图 3 局、seed 1、base 对手、亚服 kr 安装、`realtime=False`、步长 8、其他主动技能关闭。

| 方案 | 输入版本 | 胜 / 平 / 负 | 非开发图胜 / 局 | 平均敌军击杀占比 | JEV 已知用量估算 USD |
| --- | --- | --- | ---: | ---: | ---: |
| A：纯 JEV | schema 3 | 3 / 2 / 100 | 3/99 | 16.50% | 4.700458 |
| B：旧 Astra＋JEV | schema 5 | 6 / 1 / 98 | 3/99 | 30.94% | 5.915400 |
| C：P0 Astra＋JEV | schema 7 | 7 / 0 / 98 | 7/99 | 37.69% | 6.178617 |

unit_test 与 pvt_large 为开发场景。C 相对 B，平均击杀提高 19 图、持平 12 图、下降 4 图；8m、MMM、2c_vs_64zg 各增加 1 胜，mmmt 增加 2 胜，3s5z 减少 1 胜，pvt_large 减少 3 胜。每图三局共用一份计划，属于探索样本。

C 的 105 份 replay、全量交互、动作映射和冻结源码均已核验。9,759 次 JEV 请求中 9,743 次成功，16 次 API 错误由原重试恢复；SC2 非成功反馈另计 500 次 AlreadyTargeted、10 次 NotEnoughEnergy。成功采用 Astra 计划 35 份；另有原暂停时未返回用量的规划请求 1 次。

后续两项独立对照没有覆盖 C 的有效记录：

- 单位现有事实重复到问题旁边：21 个快照、两种表述各重复两次，共 84 次请求。就绪攻击选择均为 24/24，长冷却近战压迫时增大静态距离的选择均为 4/18；输入 tokens 增加 28.65%，未采用。
- pvt_large 在 P0 接口复用旧 B 计划：完成两局均负，击杀为 9、4；第三局第 3 步因 JEV HTTP 402 中断，排除出胜负统计。现有证据不支持仅靠换回旧计划恢复旧版表现。

论文固定比较 A 与 C，共 210 场微操；[逐局统计](../paper/data/study/micro_episodes.csv) 与 [方法汇总](../paper/data/study/method_summary.csv) 保留这一选择，不将 B 或未完成对照混入论文样本。

## 宏观

| 实现阶段 | 已验证结果 |
| --- | --- |
| 初始 JEV-only | Easy Zerg，20 分钟上限的平局样本 |
| Astra＋JEV / macro-v2.1 | Hard、Harder 各一胜，VeryHard/Elite 两胜 |
| macro-v2.2 | 73 项受控动作巡检通过；CheatVision、CheatMoney 各一局失利 |
| macro-v2.2.1 整理时 | 修复 HTTP 402 等永久错误的停止处理，102 项离线回归通过；该阶段尚无额度恢复后的新增实战 |

CheatMoney 的终局由独立 replay 确认为败北，原记录程序的断连状态没有被改写。CheatInsane 试验在 JEV 无额度时没有有效决策，属于诊断中止，不计作竞技败局。普通最高难度的两局胜利不能外推为对所有作弊难度或所有地图的稳定能力。

历史案例分析保留初始单模型、四场双模型胜局和一场 CheatVision 压力测试，见 [运行选择](../paper/data/study/runs.json)。论文中的模型标准 API 等价费用是已知用量估算，区别于账户账单；本页表中微观成本仅包含 JEV。

### 2026-09-24 论文宏观主表：五种配置

共同条件：Altitude LE，Protoss 对 Zerg VeryHard / Lv7，RandomBuild，handicap 100，固定种子 1–10，实时运行，每局 1200 游戏秒，决策间隔至少 1 墙钟秒。

| 配置 | 胜 | 负 | 到时限 | 样本胜率 |
|---|---:|---:|---:|---:|
| 纯随机，无 Astra、无 JEV | 0 | 10 | 0 | 0% |
| 纯 JEV，无 Astra | — | — | — | 未评估 |
| Astra 限制动作空间＋底层随机 | 0 | 10* | 0 | 0%* |
| Astra 限制动作空间＋JEV | 9 | 1 | 0 | 90% |
| Astra 不限制动作空间＋JEV | 3 | 3 | 4 | 30% |

当前发布将 Astra 作为最终系统实现介绍。建议模式“不限制”指没有 Astra 计划筛选，执行器自身的可用性及命令生命周期规则仍保留。五种配置的流程与运行命令见[配置说明](macro-configurations.md)。

纯 JEV 没有同条件 Lv7 十局；早期 Lv2 到时限样本仅作历史分析。主表合计 40 次选定对局、39 份独立验证回放，不是五组各十局。

\* Astra＋随机：9 局回放验证败北，加种子 5 的人工确认败北。该局因旧终局错误未保存 replay，原始技术核验保留未确认，不能写为十局全部回放验证。每个种子仅保留原始一次尝试，没有替换败局或到时限局。

纯随机实时批次十局全部正常结束，3,904 次选择按种子重现，模型调用为 0。旧加速纯随机同为 0/10，但不混入本表。两组 Astra＋JEV 的 15,505 次 JEV 回复和 344 次 Astra 回复均记录到推理期间游戏帧推进。

[逐局结果](../paper/data/macro_realtime/games.csv)、[配置汇总](../paper/data/macro_realtime/configurations.csv)与[协议、源码及日志哈希](../paper/data/macro_realtime/manifest.json)构成论文新主表的派生证据。历史事件、回放和开发记录保留在研究档案，不改写原始批次名称或来源。

这批是固定种子的开发样本，不能外推稳定胜率。源码及服务传递仍有版本差异；发布最终代码并不意味着此前每组都在同一最终版本重跑。因此不将结果差异归因于单一组件，也不补记未完成的纯 JEV 结果。

## 数据管理

Git 中提供论文历史统计表、新增实时宏观逐局表、来源清单和当前实现。完整请求与回复始终共同保存在本地原始 `events.jsonl`；原研究工作区的日志、计划和 replay 均保留，未为本次整理拆分、改写或删除。大体积原始档案未随 Git 发布。

当前发布版做了目录归并和依赖清理，其源码指纹与原实验冻结快照不完全相同。新实验应保存新的源码、地图哈希及配置，不能直接标成旧批次的续写。
