# 纯 JEV、无 Astra：实时 Lv7 十局实验

日期：2026-09-24。正式批次完成，**0 胜、10 负、0 局达到游戏时限，样本胜率 0%**。

10 局均自然结束并保存回放，每局 23 项核验全部通过；无技术失败、无替换对局。

## 实验设置

- 配置：`--policy jev --planner none`；模型 `jev-1.13.0`。
- 地图 Altitude LE，Protoss 对 Zerg VeryHard / Lv7，RandomBuild，双方 handicap 100。
- `realtime=True`，请求开始间隔至少 1 墙钟秒，2.5 秒请求超时，动作有效期 4 秒。
- 每局上限 1200 游戏秒、2000 次决策请求；种子 1–10，最多并行 4 局。
- 源码固定为 `9c2605ca30a0389b60d21eb80a48c708768658a3`；策略、提示词和动作执行规则未因本次结果调整。
- SC2 5.0.16.97563；SDK 已按实际客户端同步编号表，49 个 SDK Python 文件与此前实验环境一致。
- 全部请求均无 Astra 计划、指令或计划筛选，Astra 请求、回复、接受计划事件均为 0。

## 运行与动作观察

- 共 4,127 次 JEV 请求、4,100 次有效回复、24 次请求超时（0.58%），另有 3 次请求在终局关闭时取消。
- 有效回复延迟中位数 0.391 秒，P95 0.468 秒；10 局均未达到 20 分钟游戏时限。
- 4,100 次有效回复均对应请求期间游戏帧推进；心跳区间游戏时间/墙钟时间比为 0.9814–0.9989。
- 2,928 次选择 EMPTY ACTION，占有效回复 **71.4%**。其中 1,686 次发生在矿物至少 500 且存在可选训练、建造或研究动作时。此计数提示进一步审查，不能单独证明每次等待都错误。
- BUILD ASSIMILATOR 在 3,408 个请求中可选，但从未被选中；全批未发展采气。
- 心跳观测中各局最多同时拥有 1 座基地和 1 座兵营，未形成双基地经济或多兵营产能。日志仍有 11 次建基地选择和 1 次额外建兵营选择，不能说从未尝试扩张。
- 各局工兵峰值 18–27，已就绪军队人口峰值 10–16；进攻后 5 秒内切回普通防守共 87 次。

这些日志更支持优先分析宏观发展、等待和军队指令选择。较低的请求超时占比并不能证明延迟没有影响，也不足以将败局归因于单一因素。

## 技术试跑与复核边界

最初 4 次尝试使用新发布环境，遗漏了项目既有的 SC2 编号表同步步骤；SDK 编号版本为 4.11.4.78285，而游戏客户端为 5.0.16.97563。两局触发护盾电池能力编号 4113 的 KeyError，两局自然败北。四次尝试整体保留为排除的技术试跑，没有只重跑失败种子，也没有混入正式十局。

执行既有 `scripts/sync_sc2_ids.py` 后，SDK 49 个 Python 文件与此前研究环境逐字节一致，140 项宏观离线测试通过。正式十局使用相同发布源码重新从种子 1 开始。正式批次之前另有 4 次接口超时预检和 1 次成功预检，单独保留，不计入对局请求统计。

本结果是已发布纯 JEV 模式在这十个固定种子上的观测。它没有证明 JEV 在所有提示词、地图和配置下胜率为零。与其他历史批次比较时仍需披露源码与服务时序差异，不声称严格单变量因果消融。
